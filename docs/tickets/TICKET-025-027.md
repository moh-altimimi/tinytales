# TICKET-025 — Guest Management Screen

**Milestone:** M5 — Account & Settings
**Read first:** ARCHITECTURE.md §3.1 (guest_invites table), §3 (Account Structure)
**Depends on:** TICKET-023, TICKET-018

---

## Objective
Build the screen where parents can see all invited guests, their status, and revoke access.

---

## Acceptance Criteria
- [ ] `app/(app)/guests.tsx` — guest management screen
- [ ] Lists all `guest_invites` for the family account with: name (if accepted) or "Pending invite", status badge (Pending / Active), date invited
- [ ] "Invite guest" button — triggers invite flow from TICKET-018
- [ ] Free tier: "Invite guest" button disabled + tooltip shown when 2 active guests already exist
- [ ] Revoke button on each active guest row — confirmation dialog before revoking
  - Revoke: sets `guest_invites.status = 'revoked'` + deletes the `users` row for that guest (or marks inactive)
  - Revoked guests immediately lose access (Hasura permissions check against active invite status)
- [ ] Pending invites can be cancelled (sets status to 'revoked')
- [ ] Empty state: "No guests yet — invite family to share your tales"

---

├── app/(app)/guests.tsx
└── graphql/
    ├── queries/GetGuestInvites.graphql
    └── mutations/RevokeGuestInvite.graphql

# TICKET-027 — Account Deletion

**Milestone:** M5 — Account & Settings
**Read first:** ARCHITECTURE.md §3 (cascade deletes on schema)
**Depends on:** TICKET-023

---

## Objective
Allow a parent to permanently delete their account and all associated family data, complying with NZ/AU privacy legislation.

---

## Acceptance Criteria
- [ ] "Delete account" link on account screen opens a full-screen confirmation modal
- [ ] Confirmation requires the user to type "DELETE" before the button enables — prevents accidental deletion
- [ ] On confirm: calls `DeleteFamilyAccount` Hasura Action (not a direct mutation — needs elevated logic)
- [ ] Hasura Action / Postgres function performs:
  1. Delete all `tale_media` storage files from Supabase Storage (service role)
  2. Delete all `child-photos` storage files for this family
  3. Delete `family_accounts` row — cascades to all child tables via FK constraints
  4. Delete Supabase Auth user (`supabase.auth.admin.deleteUser()`) via service role
- [ ] On success: sign out locally, navigate to login screen, show message: "Your account has been deleted"
- [ ] On failure: show error toast — do not partially delete
- [ ] If the deleting user is a co-parent (not the account creator), only delete their own `users` row and Supabase Auth account — not the whole family account

---

## Files to Create
```
hasura/metadata/              # DeleteFamilyAccount action definition
```

---

## Notes
- The storage file deletion must use the Supabase service role key — this should run in a Cloudflare Worker or Hasura Action handler, not client-side
- Consider adding this handler to the existing `services/ai-pipeline` worker as a new endpoint `POST /delete-account` to avoid deploying a new service

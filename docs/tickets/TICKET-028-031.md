# TICKET-028 — Free Tier Enforcement + Upgrade Prompt

**Milestone:** M6 — Monetisation
**Read first:** ARCHITECTURE.md §8 (Free Tier Enforcement), §3.2 (family_tale_counts view)
**Depends on:** TICKET-011, TICKET-013

---

## Objective
Enforce the 25-tale free tier limit at both the server and client level, and show an upgrade prompt modal when the limit is approached or hit.

---

## Acceptance Criteria

### Server-side (Hasura)
- [ ] Hasura insert permission on `tales` table for `parent` role includes condition:
  ```json
  {
    "_or": [
      { "family_account": { "subscription": { "status": { "_eq": "active" } } } },
      { "family_account": { "tale_count_view": { "tale_count": { "_lt": 25 } } } }
    ]
  }
  ```
- [ ] If condition fails, Hasura returns a permission error — mobile app catches this and shows upgrade modal

### Client-side
- [ ] `hooks/useTaleCount.ts` — fetches the current tale count for the family account
- [ ] Home screen: when tale count ≥ 20, show a soft banner above the feed: "You've told 20 tales — [5 remaining on your free plan. Upgrade to keep going →]"
- [ ] When tale count = 25 and user taps "Post Tale": show `UpgradeModal` before inserting
- [ ] `UpgradeModal`: full-screen modal, copy "Your story library is full — upgrade to keep every moment safe", "Upgrade" CTA (→ TICKET-029), "Maybe later" dismisses modal (but post is blocked)

---

## Files to Create

apps/mobile/
├── components/UpgradeModal.tsx
├── components/FreeTierBanner.tsx
└── hooks/useTaleCount.ts
```

# TICKET-029 — In-App Subscription (RevenueCat)

**Milestone:** M6 — Monetisation
**Read first:** ARCHITECTURE.md §3.1 (subscriptions table)
**Depends on:** TICKET-028

---

## Objective
Implement the paid subscription flow using RevenueCat to handle App Store and Google Play billing. On successful purchase, write an active subscription record to the database.

---

## Acceptance Criteria
- [ ] RevenueCat SDK installed (`react-native-purchases`)
- [ ] RevenueCat project configured with:
  - iOS App Store product: `tinytales_premium_monthly` + `tinytales_premium_annual`
  - Google Play product: same
- [ ] `hooks/useSubscription.ts` — wraps RevenueCat, exposes `{ isSubscribed, subscribe, restorePurchases }`
- [ ] Subscription screen `app/(app)/subscribe.tsx`:
  - Monthly and annual price options displayed (fetched live from RevenueCat)
  - Annual option highlighted as best value
  - "Subscribe" button triggers RevenueCat purchase flow
  - "Restore purchases" link
  - Legal copy: "Subscription auto-renews. Cancel anytime in App Store / Google Play settings."
- [ ] On successful RevenueCat purchase: call `UpsertSubscription` mutation to write/update `subscriptions` row for the family account
- [ ] `isSubscribed` derived from RevenueCat entitlement — do not rely solely on the DB row for gate checks
- [ ] Zustand store updated with subscription status on launch and after purchase

---

## Files to Create
```
apps/mobile/
├── app/(app)/subscribe.tsx
├── hooks/useSubscription.ts
└── graphql/mutations/UpsertSubscription.graphql
```

---

## Notes
- RevenueCat handles receipt validation, renewals, and cancellations — do not implement these manually
- The `subscriptions` DB table is for your own reporting and Hasura permission checks; RevenueCat is the source of truth for entitlements

# TICKET-030 — PDF Book Generation

**Milestone:** M6 — Monetisation
**Read first:** ARCHITECTURE.md §5 (GraphQL), §6 (Cloudflare Worker — add new endpoint here)
**Depends on:** TICKET-029

---

## Objective
Generate a PDF preview of a memory book from the user's tales. The parent can select all tales or curate a subset. The PDF is generated server-side and returned as a download URL.

---

## Acceptance Criteria

### Mobile
- [ ] Book creation screen `app/(app)/book/new.tsx`:
  - Step 1: Choose mode — "All tales" or "Choose tales"
  - Step 2 (if curating): scrollable list of all tales with checkboxes; minimum 1 tale required
  - Step 3: Preview — "Generate preview" button triggers PDF generation
  - Loading state while generating (can take 10–20 seconds)
  - On success: PDF preview shown using `expo-file-system` + `expo-sharing` or an in-app PDF viewer
  - "Order printed book" CTA (→ TICKET-031)

### Cloudflare Worker (new endpoint)
- [ ] `POST /generate-book` added to `services/ai-pipeline` worker
- [ ] Accepts `{ tale_ids: string[], family_account_id: string }`
- [ ] Fetches full tale data from Hasura using admin GraphQL
- [ ] Generates a PDF using `pdf-lib` or `puppeteer` (Cloudflare Workers supports `puppeteer` via Browser Rendering API)
- [ ] Layout: cover page (app name + family name + date range), one tale per page (title, date, narrative, tags, photos if any)
- [ ] Uploads PDF to Supabase Storage `tale-media` bucket: `books/{familyAccountId}/{timestamp}.pdf`
- [ ] Returns `{ pdf_url: string }` — signed URL valid for 1 hour

---

└── new.tsx
services/ai-pipeline/src/
└── bookGenerator.ts          # New handler, imported in index.ts
```

# TICKET-031 — Printed Book Order Flow

**Milestone:** M6 — Monetisation
**Read first:** ARCHITECTURE.md §7 (File Storage — pdf_url from TICKET-030)
**Depends on:** TICKET-030

---

## Objective
Allow a parent to order a printed physical book using the generated PDF. In v1 this uses a print partner API (Momento or equivalent). If the print partner API is not yet contracted, implement a "notify me" placeholder flow.

---

## Acceptance Criteria

### If print partner API is available
- [ ] `app/(app)/book/order.tsx` — order screen
- [ ] Receives `pdf_url` from TICKET-030
- [ ] Collects: delivery address (name, street, city, postcode, country — AU/NZ only)
- [ ] Shows estimated price (fetched from print partner API or hardcoded in v1: $49.99 NZD)
- [ ] "Place order" button: submits PDF URL + address to print partner API via Cloudflare Worker endpoint `POST /order-book`
- [ ] Worker forwards to print partner, returns order confirmation number
- [ ] Confirmation screen: order number, estimated delivery (3–7 business days), "Done" button back to home
- [ ] Order stored in a new `book_orders` table (id, family_account_id, pdf_url, status, order_ref, created_at)

### If print partner API is not yet available (placeholder)
- [ ] "Order printed book" button shows a modal: "Printed books are coming soon — we'll notify you when they're available"
- [ ] Email capture input: pre-filled with account email, "Notify me" button
- [ ] Stores email in a simple `book_interest` table for later follow-up
- [ ] This placeholder can be replaced with the full flow above without changing any other screens

---
